# BegoFrame — инструкции для Claude

Настольная видео-студия для Windows (PySide6): из готовой озвучки собирает ролик —
расшифровка (AssemblyAI) → режиссура (Codex) → сток / инфографика / моушн-графика /
нейрогенерация картинок и видео → склейка FFmpeg. Подробности для пользователя — в [README.md](README.md).

## Устройство

- `studio/` — интерфейс.
  - `pipeline/sections.py` — параметры вкладки «Конвейер» (что видно и когда);
  - `pipeline/defaults.py` — значения по умолчанию, миграции, `image_provider()`, `source_mix()`;
  - `pipeline/runplan.py` — значения формы → env и команды движка (`common_env`, `stage_env`);
  - `pipeline/runner.py` — очередь конвейера и изменения настроек на ходу;
  - `pipeline/stages.py` — «Отдельные стадии» и «Довести проект» (берут последние значения формы «Конвейер»);
  - `catalog.py` — справочник провайдеров и моделей, общий для всех блоков.
- `engine/` — движок, запускается отдельными процессами.
  - `cli.py` — маршрут конвейера, в т.ч. `_run_post_pipeline_silent` (генерация после режиссуры);
  - `stage_runner.py` — одна стадия (transcribe / direct / imagegen / videogen / cancel);
  - `finish_runner.py` — «Довести проект» (тот же маршрут, что у конвейера);
  - `assemble.py` — склейка; `params.py` — параметры из `engine/.env`;
  - `units/` — клиенты провайдеров и логика стадий; `helpers/concat_guard.py` — готовность к склейке.
- `tools/` — сборка (`build.py`), публикация (`release.py`), иконка; `installer/` — Inno Setup и лаунчер.
- `studio/services/updater.py`, `update_ui.py`, `apply_update.py`, `prompt_sync.py` — обновления.

Три пути запуска: **конвейер** (`runplan` → `cli.py`), **отдельные стадии** (`stages.py` → `stage_runner.py`),
**«Довести проект»** (`stages.py` → `finish_runner.py` → `cli._run_post_pipeline_silent`).
Все три должны вести себя одинаково при одинаковых настройках.

## Правила работы

1. **Изменение провайдера — везде, где он используется.** Провайдер (FastGen, VeoNonStop, Vertex,
   CheapVibeCode, VARAG, CinAI, RoyalTechno и др.) встречается в нескольких местах: `catalog.py`,
   `defaults.py`, `sections.py`, `runplan.py`, `stages.py`, страницы `studio/pages/`, `params.py`,
   `cli.py`, `stage_runner.py`, `finish_runner.py`, `units/*`. Один и тот же провайдер может работать
   в нескольких блоках (картинки, инфографика, ремиксер, видео, отмена задач по «Стоп», мониторы квот).
   Меняя провайдера в одном месте, найди (`grep`) и обнови все остальные места его использования.

2. **Проверяй, что изменение действует в «Довести проект» и в отдельных стадиях**, а не только в конвейере.
   После каждой правки убедись, что новая настройка/поведение доходит до `stage_runner.py` и
   `finish_runner.py` (env, аргументы, восстановление `pipeline_config.json`), и что маршрут
   совпадает с конвейерным.

3. **Параметры «Конвейера» проверяй на разных сценариях.** Любая правка должна корректно работать при
   всех сочетаниях, а не только в одном случае. Например, при «Вислайде» видео не должно собираться
   только из видеокадров (статичные слайды должны остаться). Сценарии для проверки, как минимум:
   - тип клипов: `video` / `slideshow` / `vislide` (и интервал вислайда);
   - режим видео: `i2v` / `t2v` / `skip`;
   - «Состав видео»: только нейрогенерация, смесь сток/инфографика/моушн, нейрогенерация 0 %;
   - разные провайдеры картинок и видео, «Пропустить»;
   - формат кадра 16:9 / 9:16;
   - запуск из конвейера, отдельной стадией и через «Довести проект», в т.ч. возобновление проекта.

4. **Есть сомнения или вопросы — спрашивай и уточняй. Не гадай.**

5. Не удаляй данные пользователя: проверки и тесты не должны чистить `userdata/`, `projects/`,
   `runtime/` и `engine/.env`.

6. **После каждого изменения — загрузить в git https://github.com/Begov/updates:**
   1. commit в этом репозитории (понятное сообщение: что и зачем изменено);
   2. `python tools/release.py sync -m "<то же сообщение>"` — копирует исходники в `D:\Projects\updates`
      и делает commit + push в публичный `Begov/updates`.

   Это загрузка исходников; пользователи программы её не видят. Новая версия для них — отдельный
   выпуск (см. «Установщик и обновления»).

   Секреты в публичный репозиторий не попадают: копируются только файлы, не исключённые `.gitignore`
   (`engine/.env`, `projects/`, `userdata/`, `runtime/`, `build/`, `dist/` исключены). Не добавляй
   ключи, токены и пароли в отслеживаемые файлы.

## Установщик и обновления

- **Выпуск новой версии — только по команде пользователя** («выпусти обновление»). Порядок:
  1. поднять `APP_VERSION` в [studio/__init__.py](studio/__init__.py) (1.2.3: исправления — последняя цифра,
     новые возможности — средняя);
  2. добавить раздел `## <версия>` в [CHANGELOG.md](CHANGELOG.md) — его текст пользователь видит в окне
     обновления, писать для пользователя;
  3. `python tools/build.py` — установщик, zip-обновление и `latest.json` в `dist/<версия>/`;
  4. `python tools/release.py publish` — sync + GitHub Release `v<версия>` в `Begov/updates`.
- Как работает: программа читает `releases/latest/download/latest.json`. Если не менялась среда Python
  (`PYTHON_VERSION` в `tools/build.py` + `requirements.txt`), ставится маленький zip с кодом
  ([studio/services/apply_update.py](studio/services/apply_update.py) после выхода программы, с откатом
  при ошибке), иначе — полный установщик в тихом режиме. После установки программа перезапускается.
- Установленная программа — это байткод `.pyc` без исходников + своя среда Python (`python/`) +
  лаунчер `BegoFrame.exe` ([installer/launcher/BegoFrame.cs](installer/launcher/BegoFrame.cs)).
  Поэтому:
  - скрипты движка запускай через `paths.script(...)` / `_engine_script(...)` в cli.py, не по имени `.py`;
  - не читай исходники модулей во время работы (`inspect.getsource`, чтение `*.py`);
  - новая зависимость — в `requirements.txt` (это сменит среду: следующее обновление будет полным установщиком).
- **Данные пользователя не трогает ни обновление, ни установщик:** `projects/`, `inbox/`, `runtime/`,
  `userdata/`, `engine/.env`, `engine/instructions/`, `engine/templates/`, `engine/logs/`. Новые файлы
  с данными пользователя держи в этих папках; если появляется новая такая папка — добавь её в
  `PROTECTED` (updater.py и apply_update.py), `EXCLUDE_PREFIX` (build.py) и не перечисляй
  в `[InstallDelete]` установщика ([installer/BegoFrame.iss](installer/BegoFrame.iss)).
- Промпты и шаблоны субтитров: заводские едут в `engine/instructions_default/`; при запуске
  [prompt_sync.py](studio/services/prompt_sync.py) обновляет только те рабочие файлы, которые
  пользователь не менял. Меняешь промпт — правь `engine/instructions/` (сборка берёт заводские оттуда)
  и держи `engine/instructions_default/` в репозитории такой же.
- Иконка — [tools/make_icon.py](tools/make_icon.py) → `studio/assets/icon.ico`.
